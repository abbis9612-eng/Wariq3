# قرار التقنيات (مقترح — بانتظار موافقة المالك)

**التاريخ:** 2026-11-13 · **الحالة:** مقترح · مرتبط بـ: I-007, I-008, D-009

## المتطلبات اللي بنينا عليها القرار

1. **أندرويد إجباري** كتطبيق حقيقي (APK).
2. **3D واقعي:** صواريخ تنطلق، دخان، انفجارات، كاميرا سينمائية، مؤثرات.
3. **واجهة عربية ثقيلة:** جداول، تقارير، أزرار، لهجة عراقية، RTL كامل.
4. **التطوير يصير بواسطة Claude بسيرفر سحابي** والمالك يلعب على التلفون (ما عنده محرر ألعاب).
5. نحافظ على الكود الحالي (المحاكاة والواجهة شغالة وبدون أخطاء).

## التوصية: **TypeScript + Babylon.js + Vite + Capacitor**

| الطبقة | التقنية | ليش |
|---|---|---|
| اللغة | **TypeScript** (تتحول لـ JavaScript) | تكشف الأخطاء قبل التشغيل؛ ضرورية لمشروع يكبر وينعدل كثير. التحويل تدريجي، ملف ملف |
| محاكاة اللعبة | TypeScript صافي بدون واجهة | تنفحص آلياً آلاف المرات (التوازن)؛ ممكن تنشغل بخيط منفصل حتى ما تثقل الواجهة |
| الواجهة | HTML/CSS (الحالية) | أفضل دعم للعربي بالعالم؛ التصميم الحالي يبقى |
| الخريطة | Canvas 2D (الحالية) ثم كرة أرضية 3D اختيارية | الخريطة الحالية سريعة وواضحة |
| **3D** | **Babylon.js 9** (WebGL2 أساسي، WebGPU إذا التلفون يدعمه) | محرك ألعاب كامل: جسيمات GPU للدخان والنار، محرر جسيمات، فيزياء، إضاءة، تحميل مجسمات glTF، ومن Microsoft ويحافظ على التوافق |
| المجسمات | glTF/GLB مضغوطة (Draco/meshopt + KTX2) | معيار الصناعة؛ المصادر: Sketchfab (عندي وصول إله، نلتزم برخصة كل مجسم)، أو توليد بالذكاء الاصطناعي، أو بالكود |
| البناء | **Vite 8** | سريع، وجاهز لـ TypeScript |
| أندرويد | **Capacitor 8** | نفس الكود يصير APK؛ حفظ أصلي ما ينمسح، زر الرجوع، الاهتزاز |
| البناء التلقائي | GitHub Actions | يطلعلك ملف APK جاهز تنزله وتثبته على تلفونك |
| الفحص | Vitest (المحاكاة) + Playwright (لقطات شاشة للواجهة والـ3D) | ما أقول «خلص» بدون دليل |

### شنو نخسر بهذا الاختيار (بصراحة)
- **الأداء الخام** أقل من Godot/Unity، لأن الـ3D يشتغل داخل WebView. لعبتنا بالأدوار، والـ3D مشاهد سينمائية (إطلاق صاروخ، ضربة، معركة)، مو عالم مفتوح فيه آلاف الوحدات. فهذا كافي إذا التزمنا بميزانية أداء.
- **WebGPU داخل WebView بالأندرويد غير مؤكد** لكل الأجهزة. لهذا WebGL2 هو الأساس، وBabylon يتحول بينهم تلقائياً.

### الخطر ← الحل
- مشهد ثقيل على تلفون متوسط ← ميزانية: 30 إطار/ثانية حد أدنى، 60 هدف. نتحكم بالدقة، نبسّط المجسم البعيد، ونضغط القوام. **أول خطوة هي نموذج تجريبي يتقاس على تلفونك قبل أي التزام كبير.**
- حجم Babylon ← نستورد بس الأجزاء اللي نحتاجها، ونحمّل الـ3D بس لما يُفتح مشهد.

## متى نغيّر القرار
إذا اللعبة تحولت لاستراتيجية **مباشرة (real-time) 3D بمئات الوحدات على الأرض بنفس الوقت**، أو إذا النموذج التجريبي ما يوصل 30 إطار على تلفونك بعد التحسين ← ننتقل لـ **Godot 4.7** (مجاني ومفتوح ويصدّر أندرويد أصلي)، وننقل المحاكاة له.
